3. Product Principles

The UI and product should preserve the architectural principles already established in the backend.

3.1 Evidence Before Opinion

The product should not visually prioritize an AI-generated conclusion over the evidence supporting it.

Bad:

┌──────────────────────────────┐
│ RISK LEVEL: HIGH             │
│                              │
│ The AI believes this is...   │
└──────────────────────────────┘

Better:

┌──────────────────────────────┐
│ INVESTIGATION SUMMARY        │
│                              │
│ Coverage: 3 / 3 stages       │
│                              │
│ Verified Findings: 4         │
│ Partial Findings: 2          │
│ Contradicted Claims: 1       │
│                              │
│ Overall Assessment: Elevated │
└──────────────────────────────┘

The user should always be able to move from:

CONCLUSION
    ↓
CLAIM
    ↓
EVIDENCE
    ↓
SOURCE / METRIC / OBSERVATION
3.2 Coverage Before Confidence

One of the most important principles in DEFI-INFO is:

Silence is never safety.

The UI should make investigation coverage highly visible.

Example:

The system should never visually imply:

Instead:

No Finding

The Security Intelligence stage could not be completed.


This investigation does not provide a security assessment.
